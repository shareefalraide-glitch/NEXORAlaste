# 📘 معمارية NEXORA وحدود الخدمات

## 📖 المرجع

التقسيم أدناه يطابق الجدول 4-1 في [تقرير المشروع](reference/NEXORA_Project_Report_v3.docx): خمس طبقات وظيفية ومخزن بيانات مشترك، مع التدقيق قدرة عابرة للطبقات لا طبقة سادسة. هذا المستودع **ينفذ شريحة تأسيسية فقط**؛ الشكل المستقبلي لا يعني أن كل طبقة أو مكوّن يعمل الآن.

<div dir="ltr">

```text
L1 استشعار سلبي                Zeek / Suricata / أجهزة المؤسسة        [مخطط]
  └─ سجلات خام
L2 تطبيع وإثراء                 Vector + عقد أحداث موحد                  [عقد + استقبال محدود]
  └─ حدث مع مصدر وطابع أصلي وUTC
L3 كشف                          قواعد + Isolation Forest + دمج           [معاينة حساب فقط]
  └─ إشارة كشف موثقة المصدر والنسخة والدرجة                        [مخطط]
L4 خدمات أعمال                  Go / Fiber: ربط، حوادث، صلاحيات، تدقيق  [شريحة فعلية]
  └─ REST محمي / تحديثات مستقبلية
L5 واجهة العمليات               React / RTL / التقارير                    [عينة مستقلة]

مخزن مشترك: PostgreSQL 16 الآن للتطوير؛ Timescale والأرشفة والتخزين المستقل للأدلة لاحقًا.
التدقيق والهوية والقياس قدرات عابرة، لا يُخلط أي منها بمصدر بيانات الشبكة.
```

## 📖 التنفيذ الحالي مقابل التصميم

| الطبقة | المنفذ | غير المنفذ |
|---|---|---|
| L1 | لا توجد أداة استشعار مضمنة. كيان المصدر يدل على جهاز/باعث تملكه المؤسسة. | التقاط سلبي أو تشغيل Zeek/Suricata أو إثبات اتصال جهاز. |
| L2 | عقد JSON محدود مستوحى من ECS وواجهة داخلية لتخزين دفعات مطبّعة مع مفتاح تكرار وUTC والطابع الأصلي. | محولات Vector، مطابقة ECS الكاملة، إثراء الهوية/GeoIP/IoC، قياس انحراف الساعات، Timescale، الاحتفاظ والإنتاجية المستهدفة. |
| L3 | خدمة FastAPI مستقلة تحسب **معاينة غير تشغيلية** للمعادلة من قيم يرسلها العميل، وتمنع إدخال درجة شذوذ قبل شرط التأسيس المعلن. مدخلات العميل نفسها غير متحقق من صحتها. | تدريب Isolation Forest والسمات والتوقيعات والمعايرة والإشارات الحية والربط مع L4؛ المعاينة ليست دليل كشف. |
| L4 | Go/Fiber مع PostgreSQL: جلسات وأدوار أساسية، مصادر وأصول، أحداث مخزّنة، حوادث **يدوية** وملاحظات ومهام، تدقيق في المعاملة. عزل المؤسسة في الاستعلامات وقيود العلاقات. | ربط تنبيهات أو موافقات أو تنفيذ احتواء أو موصل خارجي، وسجل تدقيق مستقل ومرساة خارجية، وصلاحيات إنتاجية شاملة. |
| L5 | واجهة React السابقة ببيانات عرض محلية؛ حركتا الكرة والرادار كما طلب صاحب المشروع. | ربط الواجهة بـGo، جلسة متصفح حقيقية وبيانات تشغيلية. ليس زر الدخول التجريبي توثيقًا لخدمات Go. |

## ⚠️ قواعد الاتجاه والحدود

1. المستشعر L1 لا يقرر كشفًا ولا يصل مباشرة للحزم عبر L4. L2 مسؤول عن تطبيع وإثراء مصدر موثوق، وليس قرار وجود هجوم.
2. نقطة `POST /internal/v1/event-batches` الحالية تستقبل **دفعات مُطبّعة مسبقًا** من مصدر ذي رمز؛ لا تستقبل سجلات Zeek/Suricata الخام مباشرة ولا تغني عن Vector. حدها 100 حدث للدفعة؛ ليست برهانًا على هدف 2000 حدث/ثانية.
3. L3 وحده يقرر الإشارة بعد استكمال القواعد/النموذج فعليًا. لا يحوّل `risk-preview` قيم العميل إلى تنبيه أو حادثة؛ `operational=false` إلزامية.
4. L4 هو حدود الأعمال والتفويض والتدقيق. أي إجراء احتواء مستقبلي يتطلب موافقة موثقة على الإجراء والهدف وموصلًا صريحًا ونتيجة متحققًا منها؛ المهلة لا تُعرض نجاحًا. المسار غير متاح في التنفيذ الحالي.
5. L5 يعرض المنشأ والزمن والفترة ويميز `غير متاح` عن `0`. العلاقة أو اقتران سجلين لا يثبتان مسار هجوم أو اتصالًا فعليًا.

## 📖 البيانات والاعتماديات

- قاعدة PostgreSQL التشغيلية الحالية تضم المؤسسات، المستخدمين، الجلسات، الأصول، المصادر، الأحداث، الحوادث، ملاحظات التحقيق، المهام، وسجل التدقيق. مفاتيح مركبة تحصر العلاقات في المؤسسة نفسها. حذف الأصل وربطه بمخازن الأدلة وسياسات الاحتفاظ لم يُنفذ بعد.
- تسجّل عمليات الكتابة الحساسة قيد التدقيق في المعاملة نفسها، مع قفل لكل مؤسسة وسلسلة SHA-256. السلسلة **في قاعدة التشغيل نفسها** ودون مرساة خارجية؛ يستطيع صاحب صلاحيات قاعدة البيانات تجاوز الحماية وإعادة كتابتها. هذا أساس قابل للتحسين، وليس إثباتًا للسجل المستقل المطلوب في التقرير.
- الاستعلامات ذات معاملات مربوطة؛ الترقيم الحالي `limit/offset` محدود عند 10,000 ولا يلبي وحده احتياجات القراءة عالية الحجم. cursor والفهرسة والتحسين والاختبار على الحمل مهام مستقبلية.
- PostgreSQL 16 هو هدف التطوير وفق التقرير. لا يُنشئ Compose الحالي امتداد TimescaleDB أو مخزنًا باردًا؛ لا يُدّعى تحقيق سعات التقرير أو سياسة الاحتفاظ.
- `nexora.local/nexora/services/api` اسم وحدة Go محلي للمستودع لأن اسم مؤسسة GitHub لم يُحدَّد؛ يعمل داخل المستودع ولا يشير إلى منظمة حقيقية. إن أراد الفريق إصدار الوحدة كحزمة عامة فليغيّره مع الاستيرادات إلى عنوان المستودع الفعلي في تغيير مستقل.

## 🔌 العقود وإصدار 1.7

- `contracts/openapi.json`: العمليات الموجودة فعلًا؛ يفحص السكربت مطابقتها لقائمة المسارات وليس كل السلوكيات.
- `contracts/planned.openapi.json`: مسودة API للمستقبل؛ كل عملية تحمل `x-implementation-status: planned` ومالك مسار مقترح. لا توجد هذه الوظائف في الخادم الحالي، ولا ينبغي تقديمها بوصفها منجزة.
- `contracts/ml-preview.openapi.json`: عقد معاينة Python غير التشغيلية. `contracts/schemas/normalized-event.v1.schema.json`: مخطط الحدث المحدود، وليس شهادة توافق ECS.
- اختير نطاق واجهات 1.6.1 مع مقترحات 1.7. لا يظهر النص التفصيلي الكامل للمقترحات الست داخل المستندات المتاحة؛ لذلك أُدرجت مقارنات التحقيق والفترات والرسم والقوالب والتقارير كمسودات مرشحة للمراجعة، لا كمتطلبات معتمدة أو وظائف منفذة. يثبت الفريق التفاصيل والقبول البشري في `P5-07`.
