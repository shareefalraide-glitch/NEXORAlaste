## 📖 2. كيف تتصل الأجزاء؟

1. `index.html` يحمّل `src/main.jsx`، الذي يهيئ React ويستورد ملفات CSS بالترتيب.
2. `app/App.jsx` يحتفظ بحالة العرض والجلسة المحلية، وينسّق التنقل والحوارات والتحقيقات. `PageContent.jsx` يختار الشاشة من دون إضافة مكتبة توجيه أو نظام تنقل جديد.
3. كل شاشة تستورد ما تحتاجه من مجالها ومن `shared/`. بيانات السجلات الافتراضية في `data/fixtures/`، وبعض بيانات العرض المتخصصة توجد بجانب المجال المعني.
4. `app/state/useDemoActions.js` ينظم تحديث العينة والقرارات والتراجع. هذه تفاعلات في الذاكرة وليست استدعاءات API. `app/dialogs/` يفصل نموذج الحالة والإرسال والنماذج حسب المجال، مع بقاء نافذة الحوار وتجربة التركيز كما كانتا.
5. تفاصيل السجلات مقسمة في `features/investigations/details/`، ودفتر التحقيق في `notebook/`، والرسم في `graph/`. مكونات الشبكة موزعة بين الصفحة والمخطط والمقاييس والتوزيعات والخريطة.
6. واجهة `shared/ui/index.js` تعيد تصدير المكونات المشتركة من ملفات متخصصة للأزرار والحقول والجداول والحوارات. الشيفرة المشتركة لا تستورد من `features/`؛ يتحقق اختبار البنية من ذلك للاستيرادات النسبية.

ما زال `App.jsx` منسقًا رئيسيًا يحمل جزءًا من حالة الجلسة والتنقل، وما زالت الأنماط عالمية وليست CSS Modules. يمكن تقسيمهما أكثر على مراحل مع اختبارات انحدار؛ لا تُعد إعادة التنظيم هذه ضمانًا لإلغاء كل دين تقني.

## 📖 3. الأنماط وترتيبها

تُحمّل الأنماط من `src/main.jsx`. قُسّمت الأنماط الأساسية إلى ملفات متتابعة في `styles/base/`: الأساس والغلاف ومكوّنات الواجهة، النظرة العامة والجداول وأقسام الصفحات، الكشف والإدارة، النوافذ والدخول، ثم التجاوب والتعديلات التكميلية. لم يتغير تسلسل قواعد CSS عند تقسيمها.

ملفات `styles/layers/` ذات أسماء الإصدارات **فعّالة** وليست أرشيفًا؛ تبقى منفصلة للحفاظ على أولوية القواعد الحالية. لا تغيّر ترتيب الاستيراد أو تحذف طبقة لمجرد اسمها. افحص المظهرين والمقاسات والكرة والرادار والطباعة بعد أي تغيير. يفحص `npm run test:structure` الترتيب الحالي صراحةً، ويجب تحديث الفحص عمدًا عند اعتماد ترتيب جديد.

الشعارات محفوظة في `src/assets/`. تستخدم `src/assets/nexora-icon.png` في أيقونة تبويب المتصفح فقط، وتُضمَّن أثناء البناء؛ لا تُعرض داخل المنصة. لا تخلط بين ملفات العلامة ومصادر البيانات.

## 📖 4. أين أضع التعديل القادم؟

- **شاشة أو وظيفة موجودة:** داخل مجلدها في `features/`. أبقِ بيانات العينة واضحة ومنفصلة عن أي تكامل مستقبلي.
- **عنصر قابل لإعادة الاستخدام بلا اعتماد على مجال محدد:** في `shared/`، مع اختبار عند الحاجة. تجنب جعل `shared/` يستورد من `features/`.
- **نافذة نموذجية:** ابدأ من `app/dialogs/`؛ توجد المكونات المشتركة والنماذج مجمعة حسب المجال، مع حالة ابتدائية وإرسال محلي في ملفين منفصلين.
- **شاشة جديدة لاحقًا:** سجلها في `app/layout/navigation.js` وأضف اختيارها في `app/PageContent.jsx`، مع مراعاة الدليل والاختبارات. هذا توجيه للصيانة، لا اقتراح بإضافة شاشة الآن.
- **نموذج خالص قابل لاختبار Node:** استخدم استيرادًا نسبيًا كامل الامتداد عند الحاجة إلى تشغيله مباشرة خارج Vite.
- **أنماط:** استخدم رموز `styles/base/theme-tokens.css` وأبقِ أثر الترتيب معروفًا؛ راجع `DESIGN_SYSTEM.md`.
- **اختبار:** ضع اختبار الدوال في `tests/unit/`، والسيناريو بجانب مجموعته تحت `tests/`، ثم حدث أمر npm المناسب.

## ✅ 5. الأوامر ومعايير الفحص

| الأمر | الغرض |
|---|---|
| `npm ci` | تثبيت مطابق لـ `package-lock.json`. |
| `npm run dev` | تشغيل خادم Vite للتطوير. |
| `npm run build` | بناء `dist/index.html` مع تضمين التراخيص. |
| `npm run test:structure` | فحص بنية أساسية، الاستيرادات النسبية الحرفية، حدود `shared` وترتيب CSS ومداخل الاختبارات. |
| `npm run test:unit` | اختبارات النماذج والحوارات والفرز والدفتر والجلسة. |
| `npm run lint` | فحص المعرّفات غير المعرّفة، ومراجع JSX، وقواعد استدعاء React Hooks؛ ليس تدقيقًا أمنيًا شاملًا. |
| `npm run format` / `npm run format:check` | تطبيق التنسيق أو التحقق منه باستخدام Prettier. |
| `npm test` | يشغّل فحوص الجودة والبناء وسلسلة اختبارات الواجهة والمتصفحات المسماة في `package.json`. |
| `npm run test:orca` | فحص اختياري محدود على بيئة Linux مجهزة؛ ليس بديلًا عن المراجعة البشرية. |

تحتاج اختبارات المتصفح إلى `npx playwright install chromium firefox webkit`، وربما حزم نظام إضافية على Linux. اختبارات الطباعة والـPDF تخضع لقدرات المتصفح، ولا تشهد بأن PDF موسوم دلاليًا. تفاصيل التغطية والنتائج غير المحسومة في `ACCESSIBILITY_TESTING.md`.

## ⚠️ 6. حدود الأمان والتخزين

لا API ولا قاعدة بيانات ولا مصادقة أو تفويض حقيقي في المشروع. إجراءات الحوادث والفرز والموافقات محاكاة؛ العينة ليست شبكة حية، وعلاقاتها لا تثبت اتصالًا أو سببية. المسودات والبيانات المؤقتة تُمسح بالتحديث أو تسجيل الخروج، بينما قد تحفظ تفضيلات العرض غير الحساسة محليًا حسب سماح المتصفح، وتبقى الملفات التي نُزّلت على جهاز المستخدم.

حركة الكرة والرادار مستمرة بطلب صاحب النموذج رغم تفضيل تقليل الحركة؛ لم تُضف أزرار إيقاف. لم تكتمل تجربة القبول البشرية أو مراجعة النطق العربي، ولا توجد شهادة امتثال وصول. راجع `ACCEPTANCE_1_6_1.md` قبل أي اعتماد.
